# Communications Paper Skills

[English](README.md) · [安装说明](docs/INSTALLATION.md) · [使用示例](examples/README.md) · [测试记录](evaluation/REPORT.md)

一套面向通信与信息论论文的开源写作 Skill。重点是把**问题、方法、结果和证据之间的关系讲清楚**，并在改写中保留研究的技术含义与适用条件。

**当前版本：v0.1.0，实验阶段。** 项目已具备完整的规则、安装说明、示例和测试材料；写作效果仍需要真实稿件和人工反馈检验。基础测试通过不代表一定优于普通模型，也不代表达到任何期刊的录用标准。

## 能做什么

| 任务 | 交付内容 |
| --- | --- |
| 故事线梳理 | 从具体问题出发，说明已有工作的作用、未解决的问题、方法选择和结果意义 |
| Introduction 与贡献 | 调整相关工作的组织方式，补齐推理衔接，写出有证据支持的贡献 |
| 分章节写作 | 摘要、系统模型、理论、算法、结果分析、结论和图注 |
| 润色与翻译 | 改善表达，同时保留公式、符号、引用键和结论范围 |
| 自查与审稿回复 | 定位问题，提出修改，区分已完成工作、作者报告和计划工作 |
| 参考论文精读 | 标注值得学的写法，解释为什么有效、适合迁移到哪里 |

覆盖理论、性能分析、优化算法、学习方法和实验系统。提供 **TWC、TCom、TIT、ICC、GLOBECOM** 的写作侧重点，但不把某个期刊当成固定模板。也不限定 UAV、V2X、NOMA 或某种学习算法。

## 怎么开始

1. 下载或克隆整个项目。
2. 按[安装说明](docs/INSTALLATION.md)，复制完整的 `skills/communications-paper` 文件夹到所用工具的技能目录。不要只复制 `SKILL.md`。
3. 提供现有稿件或研究笔记，并说明要做故事线、写作、润色还是审查。

可直接使用的提示词：

```text
使用 communications-paper，先用中文检查下面的故事线，再修改 Introduction。
目标读者是通信领域但不研究这个具体方向的人。
解释每个方法选择的原因，让后一个问题从前面的分析中自然出现。
保留研究事实、公式和引用键。缺少的证据单独指出，不编造结果。
```

仅做语言修改时：

```text
使用 communications-paper，仅润色下面这段英文。
不改数学内容、研究结论和段落结构；技术疑问放在正文后单独说明。
```

Skill 本身不需要训练、API key 或运行库。它需要能够读取技能文件的助手；PDF 阅读、Word 编辑和文献检索使用各平台另行提供的能力。该项目可以独立查看、修改和分享，不依赖原来的聊天记录。

## 现在需要更多论文吗

**不需要先凑够某个数量。先看现有版本在哪里做得不够，再补对应材料。**

目前从两篇范文中提炼了“设计结论取决于约束”和“分析结果引出可实施控制”的写法。两篇都涉及 NOMA，其中一篇是 TVT、一篇是 TWC；这能支持初版设计，但不足以代表所有通信论文的文风。

此前提到的额外 4–6 篇只是一种可选的覆盖方案。补材料应当解决具体问题：理论叙事不清楚，补一篇定理解释出色的理论论文；方法像堆算法，补一个动机到设计的案例；修改后仍不好读，优先补一段“原稿—导师修改稿—修改原因”。将完整 PDF 堆在目录里并不会自动训练模型。

每次更新应当能回答三个问题：**学到了什么规则？适用范围是什么？换一个题目还有效吗？** 详见[参考材料扩展流程](docs/ADDING_REFERENCES.md)。

## 如何判断好不好用

已有四项小型行为检查，覆盖理论摘要、局部 LaTeX 润色、审稿回复和结果审查。另有两项新任务分别比较普通提示词与启用 Skill 的故事线、Introduction 输出。所有任务均为合成写作练习，不是新科研结果。

请阅读[测试报告](evaluation/REPORT.md)中的实际结论与局限。它保留了原始输出，便于你自行判断；没有用“测试通过”代替真实写作质量评价。

更有价值的下一步是选择一段尚未用于提炼规则的真实稿件，让两种条件各改一次，隐藏来源后由作者或导师比较：逻辑是否更连贯、技术含义是否保留、句子是否更好读、还要手改多少。

## 发布与参与修改

项目整理完成后可按[GitHub 发布指南](docs/PUBLISHING.md)上传到自己的仓库。上传源代码、安装本地 Skill 和在某个平台上发布插件是不同的操作；这里没有承诺 ChatGPT Work 的 ZIP 导入或管理页显示行为。

修改规则前请看 [CONTRIBUTING.md](CONTRIBUTING.md)。核心思想是以具体问题推动小范围修改，并用不同题目的例子检查是否过度拟合。
